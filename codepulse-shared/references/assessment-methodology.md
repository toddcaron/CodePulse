# CodePulse Assessment Methodology

1. Identify repository type, languages, frameworks, project boundaries, entry points, manifests, configuration, CI/CD, and infrastructure.
2. Define the smallest scan that can answer the active skill's questions.
3. Inspect relevant source, configuration, dependency, deployment, and authentication evidence.
4. Preserve exact evidence and record unavailable evidence or analysis limitations.
5. Normalize findings using the shared finding schema.
6. Assign severity, recommendation priority, and category score using shared references.
7. Emit an assessment result using the shared result schema.
8. Render the required report without duplicating findings.

Static analysis cannot prove the absence of vulnerabilities, unused code, exposure, or operational issues. Reports must state meaningful limitations and distinguish confirmed, potential, and unavailable evidence where relevant.
