# HTML Renderer (Detailed Reports)

Render a `reportType: "detailed"` object conforming to `../schemas/codepulse-report-schema.json` into one self-contained HTML file. The JSON is the only data source: do not add facts, findings, or scores that are not in it.

## Rules

- HTML-escape every JSON string (`& < > " '`). Never emit raw HTML, `<script>`, inline event handlers, or `style` attributes from JSON content.
- Links: render only `http://` or `https://` URLs, as `<a href="…" rel="noopener noreferrer">`.
- Render paths, commands, versions, CVE/GHSA ids, and finding ids inside `<code>`. Never shorten or rewrite them.
- Omit an optional section when its data is absent or empty, except the sections listed as required for `codepulse-full`, which render `None identified in the reviewed scope.` or the capability status instead.
- Show `unavailable` for `null` scores or grades. Never hide a non-`complete` status.
- No JavaScript, external fonts, images, or stylesheets.

## Skeleton

```html
<!doctype html>
<html lang="en"><head><meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1">
<title>{application} – {skillName} – {assessmentDate}</title><style>{CSS}</style></head>
<body><main>{SECTIONS}<footer>Generated by {skillName} for {application} on {assessmentDate}. Grades summarize current evidence and are not a compliance certification.</footer></main></body></html>
```

## Components

- **Grade badge** `G(grade)`: `<span class="g {grade}">{grade}</span>`; `null` → `<span class="g">–</span>`. Add class `big` for the overall grade.
- **Finding** `F(finding)`: class = `severity`, or `positive` when `status` is `positive`.
  ```html
  <div class="f {class}" id="{id}"><p><strong><code>{id}</code> {severity}: {title}</strong></p>
  <p>{impact}</p><ul>{evidence → <li>EVIDENCE</li>}</ul>
  <p><strong>Recommendation:</strong> {recommendation}</p>
  <p class="meta">{verificationStatus} · {sourceRepresentation}{evidenceRecoveryRequired ? " · original evidence recovery required" : ""}{evidenceLimitations joined "; "}</p></div>
  ```
  - EVIDENCE string → escaped text. Object → `<code>{path}:{line}[-{endLine}]</code>` or `<code>{command}</code>`, then `{symbol}`, `<pre><code>{snippet|output}</code></pre>` and `{note}` when present.
  - Append `cveInformation` as `<li><code>{id}</code> {package} {version} → {fixedVersion} (CVSS {cvss})</li>` and `referenceLinks` as links.
  - Order findings by severity: Critical, High, Medium, Low, Informational, no severity, positive.
- **Finding reference** `R(id)`: `<a href="#{id}"><code>{id}</code></a>`.

## Section Order

Each section is `<section><h2>{Title}</h2>…</section>` unless shown otherwise.

| # | Title | Source | Markup |
|---|---|---|---|
| 0 | header | `skillName`, `assessmentDate`, `application` | `<header><div class="eyebrow">CodePulse / {skillName} / {assessmentDate}</div><h1>{application}</h1><p class="meta">{repository}</p></header>` |
| 1 | Executive Summary | `executiveSummary[]` | one `<p>` per item |
| 2 | Assessment Dashboard | `assessments[]` | table: Category, Status, Score, Grade, Summary. Add `skipReason` to Status when present. |
| 3 | Overall Grade | `overall` | `<div class="head">` with `G(grade) big`, `{score} / 100`, and `note`. If `complete` is false, prefix `Incomplete assessment:`. |
| 4 | Assessment Methodology | `methodology`, `scope` | lists: Executed checks (`<code>`), Tools, Notes, Included, Excluded |
| 5 | one per `assessments[]` item | see table below | `<div class="head"><h2>{title}</h2>{G(grade)}</div>`, `<p>{summary}</p>`, status line when not `complete`, metrics, `F()` per finding (resolve string ids to the full record elsewhere in the report and render `R(id)`), `limitations` list |
| 6 | Codebase Metrics | `loc` metrics from `codepulse-loc` assessment | table: Language, Files, Physical, Nonblank; bold totals row; exclusions list |
| 7 | Top Risks | `topRisks[]` | `<ol>` of `R(findingId)` + finding title + `summary` |
| 8 | Recommendations | `recommendations[]` | `<ol>` of `<strong>{priority}: {title}</strong> {detail}` + `R()` per `findingIds` |
| 9 | Modernization Opportunities | `modernization[]` | `<ul>` of `<strong>{title}</strong> {detail}` + `R()` |
| 10 | Limitations | `limitations[]` | `<ul>` |
| 11 | Conclusion | `conclusion` | `<p>` |

Assessment section titles:

| `assessmentName` | Title |
|---|---|
| `codepulse-loc` | Lines of Code |
| `codepulse-vuln`, `codepulse-vuln-verbose` | Security Assessment |
| `codepulse-quality` | Code Quality Assessment |
| `codepulse-deadcode` | Dead Code Assessment |
| `codepulse-plm` | Dependency & Framework Assessment |
| `codepulse-ext` | External Exposure Assessment |

Category metrics inside an assessment section:

- `metrics.complexity.measures` → `<h3>Complexity breakdown</h3>` table: Measure, Source, Functions, Median, P90, Max, Above threshold, Score. Show `note` across the empty columns when numbers are absent.
- `metrics.complexity.hotspots` → `<h3>Complexity hotspots</h3>` table: Function, Location (`<code>`), Cyclomatic, Cognitive, Finding (`R()`), Note.
- `metrics.loc` → render under section 6, not in the assessment section.

## Required Sections By Skill

- `codepulse-full`: all sections 0–11. The six assessment sections must all render, including any with a non-`complete` status.
- Focused skills: sections 0, 1, 3, 4, their own assessment section, then 7–11 when data exists. `codepulse-loc` also renders 6.
- `codepulse-vuln-verbose`: under the Security Assessment section, add `<h3>Coverage appendix</h3>` from `methodology.notes` and list every evidence location.
