Executive Summary

The only executable source in this repository is validate-codepulse.ps1, a 185-line PowerShell validation script. It is readable, flat, and fails fast with specific error messages; every top-level statement is within acceptable cyclomatic and cognitive thresholds.

Maintainability cost comes from repetition rather than difficulty: the same contains-or-throw guard is hand-written in 18 places, string comparisons are inconsistent, and the script stops at the first failure. A small data-driven helper would remove most of this accidental complexity.

Findings

QUAL-ACC-001 Low: Contains-or-throw guard duplicated 18 times

Each new contract rule requires copying a loop, guard, and message. Inconsistencies (see QUAL-001) creep in because each copy is written independently.

  • validate-codepulse.ps1:67-72
    foreach ($weight in @(...)) {
    if ($full.IndexOf($weight) -lt 0) { throw "codepulse-full is missing weight: $weight" }
}
  • validate-codepulse.ps1:124-130 Same pattern for both renderers
  • validate-codepulse.ps1:136-183 Same pattern for runtime contract, token efficiency, orchestration, setup doc, and benchmark plan
  • Select-String validate-codepulse.ps1 -Pattern '\.IndexOf\('
    18 matches

Recommendation: Inherent-vs-accidental test: the same behavior can be expressed more simply. Replace with one helper, e.g. Assert-Contains -Path <file> -Items <string[]> -Label <text> [-IgnoreCase], driven by a table of file-to-required-text entries.

QUAL-ACC-002 Low: Skill inventory hardcoded in three places

Adding or removing a skill requires editing magic numbers and an exclusion list that duplicate the skillName enum in codepulse-report-schema.json.

  • validate-codepulse.ps1:32
    if ($allSkills.Count -ne 10) { throw ... }
  • validate-codepulse.ps1:35
    if ($skills.Count -ne 9) { throw ... }
  • validate-codepulse.ps1:112
    Where-Object { $_.Name -ne 'codepulse-shared' -and $_.Name -ne 'codepulse-full' -and $_.Name -ne 'codepulse-exec' }

Recommendation: Derive the expected skill list from the skillName enum in codepulse-shared/schemas/codepulse-report-schema.json and compare sets, instead of hardcoding counts and names.

QUAL-001 Low: Inconsistent string comparison semantics

Readers must check each call to know whether a rule is case-sensitive. Culture-sensitive IndexOf can behave differently across locales.

  • validate-codepulse.ps1:50 IndexOf without StringComparison (culture-sensitive, case-sensitive) also at lines 55, 61, 68, 71, 76, 82, 125, 129, 131, 137, 141
  • validate-codepulse.ps1:144 IndexOf with OrdinalIgnoreCase also at lines 151, 167, 168, 175, 180
  • validate-codepulse.ps1:58
    if ($text -match 'report-template\.html|...')
    -match is case-insensitive

Recommendation: Use one comparison policy: StringComparison.Ordinal for exact contract text, OrdinalIgnoreCase only where intentional. Centralize it in the QUAL-ACC-001 helper.

QUAL-002 Low: Validation stops at the first failure

Contributors fixing a broad change (such as this report migration) must rerun the script once per defect.

Recommendation: Collect failures into a list, print all of them, and exit 1 when any exist.
