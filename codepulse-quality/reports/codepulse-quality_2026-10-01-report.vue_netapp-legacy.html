QUAL-ACC-001 · Low · Request/loading/error plumbing duplicated across views.

Evidence: Same loading = true; error = null; try { axios … } catch (e) { error = e.message } finally { loading = false } shape in DashboardView.vue:21-32, RequestListView.vue:18-29 (identical to Dashboard), RequestDetailView.vue:17-28, :30-41, :43-56, and CreateRequestView.vue:14-32. API URLs are built by string concatenation inline (e.g. '/api/requests/' + request.value.id + '/status').
Inherent vs. accidental: Accidental. The same behavior can be expressed with one API module and one async-state composable without losing correctness.
Impact: Six copies to change for any cross-cutting concern (auth header, base URL, error mapping, retries).
Recommendation: Add src/services/requestsApi.js for endpoints and a useAsync() composable for loading/error state.
verified-original · original

QUAL-ACC-002 · Low · Status values defined in four places.

Evidence: RequestListView.vue:11 and RequestDetailView.vue:11 declare ['New', 'InProgress', 'Blocked', 'Completed']; DashboardView.vue:12 hardcodes the same keys; the server source of truth is enum RequestStatus in Models/OperationalRequest.cs:13-19.
Inherent vs. accidental: Accidental. The status set is a domain rule, but repeating it is not required.
Impact: Adding a status needs four coordinated edits; a missed one silently drops counts on the dashboard (counts[r.status] !== undefined guard).
Recommendation: Export one REQUEST_STATUSES constant in the client, or serve it from the API.
verified-original · original

QUAL-ACC-003 · Informational · Redundant enum-to-string conversion.

Evidence: RequestDto.Status is string (Models/RequestDto.cs) and RequestService.ToDto calls r.Status.ToString() (RequestService.cs:86), although JsonStringEnumConverter is already registered (Program.cs:8).
Inherent vs. accidental: Accidental. Two mechanisms do the same job, and the DTO loses type safety.
Recommendation: Type RequestDto.Status as RequestStatus and rely on the converter.

QUAL-001 · Medium · Singleton service mutates shared state without synchronization.

Evidence: builder.Services.AddSingleton<RequestService>() (Program.cs:6); RequestService holds List<OperationalRequest> and _nextId/_nextCommentId counters (RequestService.cs:7-9) incremented with ++ (:43, :73) and mutated by Add/AddComment with no lock.
Impact: Concurrent requests can produce duplicate IDs or corrupt/enumerate the list during mutation.
Recommendation: Use ConcurrentDictionary with Interlocked.Increment, guard with a lock, or move to a scoped persistence layer.

QUAL-002 · Low · Inconsistent server-side validation.

QUAL-003 · Low · Raw transport errors shown to users; no client logging.
